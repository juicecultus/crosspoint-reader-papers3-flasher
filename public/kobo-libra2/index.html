EinkHub / Kobo Libra 2

InkHub

A Linux operating system for the Kobo Libra 2.

Put InkHub on your Libra 2, from this page

This page talks to your e-reader over the USB cable. It can run the whole system from memory without writing anything to the device, and it can install it. It works in Google Chrome and Microsoft Edge on a computer.

What you get

A mainline Linux kernel, a launcher drawn to match the stock reader's own screens, KOReader, a terminal, Wi-Fi, the frontlight on Kobo's own calibration, and no store and no account. The source is on GitHub and everything on the image is built from it.

What you lose

Kobo's own software stops running. No Kobo sync, no Kobo store, no Overdrive, and no Kobo reader. Your device stops being a Kobo until you put it back.

What is kept, and what is not

  • Your books are kept. They live on the device's third partition and nothing on this page writes to it.
  • Reading positions and annotations are not kept. They belong to Kobo's reader, which stops running.
  • The recovery partition is never touched, and neither is the bootloader or your device's serial number and panel calibration. Everything Kobo needs to put itself back is still on the device afterwards. Reaching it is a stock reinstall over USB, or an action in this system's own Settings, and it is not the button gesture: see what this page can and cannot do.

A browser cannot take a backup, and the project's own rule is that you take one

The documented way to install InkHub starts with a verified copy of the whole card on two machines, because that copy is the only thing that puts your device back byte for byte. Fastboot has no read command at all, so this page cannot take that copy and cannot check one exists.

What is left instead is putting Kobo's own software back, which this flow never makes impossible: everything that does it is still on the device afterwards. That is a real net and it is not the same net: it gives you back a stock Kobo, not your device exactly as it was, and it reformats the partition your books are on.

If you want the full backup first, it is docs/second-device.md in the repository. It needs a shell on the device and an evening.

    5 Try it, or install it

    Try InkHub Live

    Writes nothing at all

    The whole system, running from memory. The launcher, the terminal, the display, the frontlight, Wi-Fi and your own books, mounted read only. KOReader is not in this image; it is too large to boot from memory, and the tile on the home screen says so.

    Nothing you do in a live session is saved. Hold the power button, turn the device back on, and your Kobo is exactly as it was.

    Install InkHub

    Writes to the device

    Replaces the system partition, the kernel and the device tree. Your books are on a different partition and are not touched. Kobo's own software is gone until you restore it.

    Read what this page can and cannot do below before you start. At the end you power the device off and on by hand.

      What this page can and cannot do
      

	
      It can
      
	
        
		
      • Read the four things the bootloader will say about itself, and refuse anything that is not a Libra 2.
        • 
		
      • Send the live image and run it from memory, writing nothing.
        • 
		
      • Write the system partition, the kernel slot and the device tree. Those three writes are the whole install: the bootloader itself sets up the small record it reads on every start to find the device tree.
        • 
		
      • Start a small program from memory afterwards, when the release carries one, which reads all three back on the device and says on the screen whether each one matched.
        • 
	
      

	
      It cannot
      
	
        
		
      • 
			Take a backup. Fastboot has no read command. Nothing on the
			card can be copied off through this cable.
		
        • 
		
      • 
			Read anything back itself. The same missing command means
			nothing written here can be checked from the browser. That is what the small
			program on the device is for. If the release does not carry it, the install
			is still complete and the first start is the check.
		
        • 
		
      • 
			Keep your Bluetooth firmware. The Realtek Bluetooth blobs are
			not this project's to redistribute, and the on-device installer copies them
			off your own stock system before it replaces it. This route replaces it
			without that copy, so Bluetooth will have no firmware afterwards.
		
        • 
		
      • 
			Restart the device. You power-cycle it by hand at the end.
			That is not a fallback for when something goes wrong; it is the step.
		
        • 
	
      

	
      The way back to Kobo
      
	
      
		It is a stock reinstall over USB, or, once it has been proven on real
		hardware, an action in this system's own Settings that hands the device
		back to Kobo's recovery. It is not the button gesture.
		Holding power and a page key together does give you a stock Kobo back on
		a device that is still running Kobo's software, and we have watched it
		do exactly that. It does not fire on a device running this system: it
		was held four times, on two builds, and every attempt was an ordinary
		start. The recovery partition itself is never touched by any of this,
		which is what both routes back rely on.
	
      

      



      
	
      If something goes wrong
      
	
        
		
      • Nothing appears in Chrome's device picker. The device is not in fastboot. Power it fully off and try step 3 again. A failed attempt costs nothing.
        • 
		
      • It appeared once and then stopped. Plug the cable directly into the computer. The bootloader's USB does not survive a hub, and the first attempt after entering fastboot is unreliable in general.
        • 
		
      • Chrome could not open the device. On Windows the fastboot interface needs the WinUSB driver bound to it. On Linux it needs a udev rule. macOS needs nothing.
        • 
		
      • The device will not boot after an install. Power it fully off and put it back in fastboot, then install again, or send it Kobo's own software instead. Do not rely on holding power and a page key: that gesture is decided before any of this runs and it does not fire once these writes are on the device, which was held four times on two builds and measured. What puts a Kobo back is a stock reinstall over this same cable.
