InkHub

A Linux operating system for the Kobo Libra 2.

Put InkHub on your Kobo Libra 2

It all happens here, over the USB cable, in Chrome or Edge on a computer. Nothing to install first. Try the whole system from memory without writing anything to your e-reader, or install it when you are ready.

3 Put the device into fastboot

Fastboot is a small mode inside the device's own bootloader. Plug the cable straight into your computer, not through a hub, then:

  1. Power the device fully off.
  2. Hold the TOP page-turn button.
  3. Short-press power, and keep holding the top button for ten seconds.
  4. The screen stays dark. That is right, and the page will see the device.
If the device does not appear
  • An empty picker means the device is not in fastboot yet. Power it fully off and run the four steps again. A failed attempt costs nothing.
  • Try a different cable and a port on the computer itself. The bootloader's USB does not survive a hub.
  • On Windows the fastboot interface needs the WinUSB driver bound to it, and on Linux a udev rule. A Mac needs nothing.

4 Connect

Live from memory, nothing written

5 Try InkHub Live

The whole system runs from memory: the launcher, the terminal, Wi-Fi, the frontlight, and your own books, mounted read only.

Nothing is saved and nothing is written. Hold the power button until the device goes off, turn it back on, and your Kobo is exactly as it was.

KOReader is not in this one

A live image has to fit in memory and KOReader is too big to come along. The tile on the home screen says so. An install has it.

Writes to the device

5 Install InkHub

This writes the system, the kernel and the device tree, and from then on InkHub is what your Libra 2 starts.

Your books stay. They live on the third partition and nothing here writes to it. Kobo's reading positions and annotations do not come across: they belong to Kobo's reader, which stops running.

You do not need a backup to come back. The way back uses the recovery partition, and that is one of the things this page never writes to.

What is never touched

The recovery partition, the bootloader, your device's serial number and the panel calibration. Everything Kobo needs to put itself back is still on the device afterwards.

The full byte-for-byte copy

A complete copy of the card is a developer's procedure: a shell on the device, a second machine and an evening. It is docs/second-device.md if you want one.

Go back to Kobo

Open Settings in InkHub, go to Device information, and choose Go back to Kobo on the last sheet. That is the whole thing.

It erases the device the way a Kobo factory reset does and hands it back to Kobo's own software, so copy anything you want to keep off the device first.

The other way back

Kobo's own firmware, sent over this same cable. It needs no InkHub running at all, which is why it is the one to reach for if the device will not start.

The button gesture is not the way back

Holding power and a page key together is Kobo's factory restore, and it only fires with Kobo's own images in the slots. On a device running InkHub it is an ordinary start, every time we have tried it.

What you get

A mainline Linux kernel, a launcher drawn to match the stock reader's own screens, KOReader, a terminal, Wi-Fi, and the frontlight on Kobo's own calibration. No store and no account. The source is on GitHub and everything on the image is built from it.

What you lose

Kobo's own software stops running: no Kobo sync, no Kobo store, no Overdrive, no Kobo reader. Bluetooth has no firmware after an install from this page, because those files are not ours to hand out.

Browsers

Chrome or Edge, on a computer. Safari has no WebUSB, so it cannot reach the device at all. Windows should work and we have not tested it.

The first start on a Mac

A Mac asks once whether to allow the new device the first time InkHub starts. Allow it, or the cable carries nothing.

What this page can and cannot do

It can read the four things the bootloader will say about itself, run the live image from memory, and write the system, the kernel and the device tree. Those three writes are the whole install.

It cannot read anything back, because fastboot has no read command. When a release carries the small checking program, this page starts it from memory and the device says on its own screen whether each part matched. When a release does not carry it, the install is still complete and the first start is the check.

It cannot restart the device either. You power it off and on by hand at the end, and the page tells you when.

If something goes wrong
  • It stopped part way. Unplug the cable, hold the power button until the device goes off, and start again at step 3. Nothing further was sent.
  • It will not start after an install. Power it fully off, put it back in fastboot and install again, or send it Kobo's own software over the same cable.
  • The browser could not open the device. On Windows the fastboot interface needs the WinUSB driver bound to it, and on Linux a udev rule.
